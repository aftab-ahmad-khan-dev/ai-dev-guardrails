# Push Report


## ⚡ Command

```text
/push-report
# or ask the agent:
use skill push-report
```

## Overview

Every push leaves an auditable markdown trail in **`REPORT.md`** at the project root (append a new dated section; never erase history). Covers security, warnings, quality gates, and git metadata.

## When to use

- Before `git push` / as part of ship
- User asks for a security report, push report, or release notes for a push
- After local scans (lint, test, gitleaks, audit)

## Process

### 1. Gather (run from repo root)

Prefer the helper script when present:

```bash
bash skills/push-report/scripts/generate-push-report.sh
# or after pack install:
bash .cursor/skills/push-report/scripts/generate-push-report.sh
```

If the script is missing, gather manually:

| Signal | How |
|--------|-----|
| Branch / HEAD / ahead-behind | `git status -sb`, `git rev-parse --short HEAD` |
| Commits in this push | `git log origin/<branch>..HEAD` (or since last REPORT section) |
| Dirty tree | `git status --porcelain` |
| Secrets | gitleaks / `ggshield` / pack SEC scan checklist — note tool + result |
| Dep audit | `npm audit --omit=dev` / `pip-audit` / equivalent |
| Lint / typecheck / test / build | project scripts; record pass/fail + excerpt |
| Client exposure | public env keys, tracking IDs (CS/SEC rules) |
| Design/slop (if UI changed) | note slop-catalog run yes/no |
| Warnings | compiler, linter, deprecations — list non-zero |

### 2. Write REPORT.md

- If `REPORT.md` missing, create from the template below with a title + legend.
- **Append** a new `## Push — YYYY-MM-DD HH:MM TZ` section at the top (newest first) or bottom (oldest first) — pick one convention and keep it; default **newest first** after the legend.
- Do not delete prior push sections.
- Mark anything not run as `NOT RUN` (honest) — never fake PASS.

### 3. Gate

- `FAIL` on secrets or critical security → **do not push** until fixed (unless user overrides explicitly).
- `WARN` → push allowed only if noted in REPORT with rationale.
- Offer to open/commit `REPORT.md` with the push.

## REPORT.md template (bootstrap)

```markdown
# REPORT.md — Push & Security Log

> Newest sections first. Generated by skill `push-report`.
> Legend: `PASS` · `FAIL` · `WARN` · `N/A` · `NOT RUN`

## Legend
| Status | Meaning |
|--------|---------|
| PASS | Check ran and succeeded |
| FAIL | Check ran and failed — block push if security-critical |
| WARN | Non-blocking issue recorded |
| N/A | Not applicable to this project |
| NOT RUN | Tool/script not executed this cycle |
```

## Safety

- Never delete `REPORT.md` history.
- Never force-push to rewrite evidence without explicit user request.
- Follow `safe-file-ops` / pack SAFETY rules.

## Verification

- [ ] New section appended with honest statuses
- [ ] Security FAIL blocks recommendation to push
- [ ] Script used when available
- [ ] User can open `REPORT.md` and see this push
