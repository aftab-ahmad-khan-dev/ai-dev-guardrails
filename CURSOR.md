# 🛡️ PRIORITY #1 — SECURITY-FIRST

**Security is the highest priority and must be checked before any action.**

Before:

* implementing a feature
* fixing an issue
* changing dependencies
* installing packages
* updating packages
* executing unfamiliar code
* modifying configuration
* modifying project files

Cursor must perform the appropriate security pre-check first.

Never skip the security gate.

---

# 🔍 SESSION-START SECURITY CHECK

At the beginning of every new Cursor session:

1. Inspect the project structure.

   * Skip `node_modules`.
   * Skip `.git`.
   * Skip build artifacts.
2. Inspect:

   * `package.json`
   * lockfiles
   * relevant configuration
3. Search for:

   * secrets
   * credentials
   * API keys
   * access tokens
4. Review:

   * suspicious scripts
   * suspicious dependencies
   * obvious SAST issues
5. Use available security tools when already installed.
6. Output:

**Security Status: Clean**

or:

**Security Status: Issues Found — <brief description>**

7. Only then proceed with the requested task.

---

# 🛡️ DEPENDENCY SECURITY GATE

Before installing any dependency:

1. Inspect `package.json`.
2. Inspect lockfiles.
3. Inspect dependency versions.
4. Inspect lifecycle scripts.
5. Inspect package source/provenance where possible.
6. Check known security concerns.
7. Check for established alternatives.

Do not install first and investigate later.

---

# 🔒 SAFE INSTALLATION

When installation is explicitly approved:

Prefer:

```bash
npm ci --ignore-scripts
```

or:

```bash
npm install --ignore-scripts
```

Then perform appropriate security checks.

Do not automatically enable:

* `preinstall`
* `install`
* `postinstall`
* `prepare`

Only enable lifecycle scripts when required and reviewed.

---

# 🚨 SUSPICIOUS DEPENDENCY RULE

If a dependency appears suspicious because of:

* typosquatting
* dependency confusion
* unexpected lifecycle scripts
* unexpected network activity
* unexpected filesystem access
* heavy obfuscation
* credential access
* remote downloads
* suspicious binaries
* crypto-mining behavior
* unrelated functionality

then:

**STOP → REPORT → DO NOT INSTALL → RECOMMEND A SAFE ALTERNATIVE.**

# 📊 TRACKER WORKFLOW

When receiving new work:

1. Parse the request.
2. Determine:

   * `feat`
   * `fix`
   * `security`
   * `update`
   * `issue`
   * `feat/fix`
3. Normalize the task.
4. Find the highest existing task number.
5. Assign the next sequential number.
6. Add it unchecked.
7. Immediately add the Comment.
8. Perform security checks.
9. Implement only that task.
10. Update the Comment when necessary.
11. Mark `[x]` after successful completion.
12. Add completion date/time.
13. Add verified GitHub username.
14. Add token usage when available.
15. Update `Last updated`.

---

# 🔢 TASK NUMBERING

* Never reuse task numbers.
* Never renumber completed tasks.
* Never delete completed history.
* New task number = highest existing number + 1.
